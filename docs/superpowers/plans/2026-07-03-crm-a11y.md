# Accesibilidad WCAG 2.1 AA — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Llevar el frontend de LeadHub a WCAG 2.1 AA: teclado, lectores de pantalla, contraste (claro/oscuro), labels y semántica. Solo web; sin cambios de esquema/API.

**Architecture:** Tokens de contraste en `index.css` (+ Tailwind) para faint/danger/accent-btn; ScoreBadge AA; teclado en Kanban (onKeyDown + KeyboardSensor + announcements); drawer como diálogo modal (role/aria + focus trap + Escape + retorno de foco); `aria-live` en toasts/Loading/jobs; labels/landmarks/headings en todas las superficies.

**Tech Stack:** React 18 + Tailwind (tokens CSS vars) + @dnd-kit + react-router. TypeScript ESM.

## Global Constraints

- **SIN tests automatizados** (política). Verificación por build verde + **re-scan axe** (claro/oscuro) + smoke de teclado (lo corre el controlador). No agregar tests. No romper tests del monorepo.
- **Value-imports de `@leadhub/core` desde web SOLO por subpaths** (`/stages`, `/score`).
- **Conservar TODA la lógica** (queries, mutaciones, drag optimista, filtros en URL, invalidaciones, toasts). Los cambios son de accesibilidad/estilo, no de comportamiento de datos.
- Colores por tokens; el `bg-black/30` del scrim del drawer se permite. `stageColor` se usa para puntos/barras/bordes (no como texto).
- Commits en español, formato convencional, usando EXACTAMENTE:
  `git -c user.name="Emanuel Cejas" -c user.email="emanuel.cejas.ar@gmail.com" commit -m "..."`

## File Structure

- `apps/web/src/index.css`, `apps/web/tailwind.config.js` — tokens (faint, danger, accent-btn) + `.btn`.
- `apps/web/src/components/ScoreBadge.tsx` — badge AA.

- Componentes que usan `stageColor` como texto (`KanbanCard`, `Tareas`, `LeadDrawer`) — cambiar a `text-danger`.

### Task 2: Teclado — Kanban

**Files:**
- Modify: `apps/web/src/components/KanbanCard.tsx`
- Modify: `apps/web/src/components/KanbanBoard.tsx`

**Interfaces:**
- Consumes: `stageLabel` de `@leadhub/core/stages` (para anuncios). `@dnd-kit/core` exporta `KeyboardSensor`.

**Contexto:** conservar el drag optimista, el filtro client-side, el `DragOverlay`, `useReducedMotion`. Solo se agrega accesibilidad de teclado.

- [ ] **Step 1: `KanbanCard.tsx` — abrir por teclado + aria-label**

Al `div` raíz de la tarjeta (el que tiene `onClick={() => onOpen(card.id)}` y el spread de `useDraggable`), agregar:
```tsx
      onKeyDown={(e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); onOpen(card.id); } }}
      aria-label={`${card.nombre}, prioridad ${card.score}${card.proximoVence && new Date(card.proximoVence).getTime() < Date.now() ? ', con tarea vencida' : ''}`}
```
(No quitar el spread de `useDraggable` — `attributes` ya aporta `role="button"`/`tabIndex`; el `aria-label` explícito mejora el nombre. Conservar el resto.)

- [ ] **Step 2: `KanbanBoard.tsx` — KeyboardSensor + anuncios + roles de lista**

Ampliar el import de `@dnd-kit/core` para incluir `KeyboardSensor`.
Cambiar `useSensors(useSensor(PointerSensor, { activationConstraint: { distance: 5 } }))` por:
```tsx
  const sensors = useSensors(
    useSensor(PointerSensor, { activationConstraint: { distance: 5 } }),
    useSensor(KeyboardSensor),
  );
```
Agregar anuncios en español al `DndContext` (prop `accessibility`), usando `stageLabel` para la etapa destino:
```tsx
    <DndContext
      sensors={sensors}
      onDragStart={onDragStart}
      onDragEnd={onDragEnd}
      accessibility={{
        announcements: {
          onDragStart: ({ active }) => `Tomaste la tarjeta ${String(active.id)}.`,
          onDragOver: ({ over }) => (over ? `Sobre la etapa ${stageLabel(String(over.id))}.` : 'Fuera de las etapas.'),
          onDragEnd: ({ over }) => (over ? `Soltaste en ${stageLabel(String(over.id))}.` : 'Cancelado.'),
          onDragCancel: () => 'Movimiento cancelado.',
        },
      }}
    >
```
En `Column`, envolver la lista de tarjetas con `role="list"` y darle un heading accesible: el `<span>` del título de columna pasa a `<h2 className="...">` (o mantener el span y agregar `role="heading" aria-level={2}`), y el contenedor de tarjetas `role="list"`; cada `<KanbanCard>` no necesita `role="listitem"` porque el div ya es `role="button"` — en su lugar, poné `role="list"` en el wrapper y dejá las tarjetas como botones dentro (aceptable), o envolvé cada tarjeta en un `<div role="listitem">`. Elegí la opción simple: `role="list"` + `aria-label={label}` en el contenedor de tarjetas de la columna.

- [ ] **Step 3: Build** — `pnpm --filter @leadhub/web build` → verde.
- [ ] **Step 4: Commit** — `... commit -m "fix(a11y): Kanban operable por teclado (onKeyDown, KeyboardSensor, anuncios en español, roles de lista)"`.

- [ ] **Step 2: `Pipeline.tsx` — retorno de foco**

```tsx

```
